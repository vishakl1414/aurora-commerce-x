Week 1


Day 1


Q1: Spring Boot kya hai?
A: Spring Boot ek Java framework hai jo web applications aur REST APIs banane ke liye use hota hai. Ye Spring Framework ke upar bana hai lekin isme configuration bahut kam karni padti hai — "convention over configuration" follow karta hai.

Q2: REST API kya hota hai?
A: REST API ek tarika hai jisse do systems internet ke through communicate karte hain. Client (frontend/app) server ko HTTP request bhejta hai aur server response deta hai — usually JSON format mein.

Q3: @RestController annotation kya karta hai?
A: Ye Spring ko batata hai ki ye class HTTP requests handle karegi aur directly data return karegi (JSON/String) — koi HTML page nahi.

Q4: @GetMapping kya hota hai?
A: Ye annotation ek method ko HTTP GET request se map karta hai. Jab user browser mein /hello open karta hai toh GET request jati hai aur wo method call hoti hai.

Q5: Port kya hota hai?
A: Port ek number hota hai jisse computer different services ko alag karta hai. Spring Boot default port 8080 use karta hai. Agar wo busy ho toh hum application.properties mein change kar sakte hain.

Q6: Spring Initializr kya hai?
A: Ye ek website (start.spring.io) hai jo automatically Spring Boot project ka basic structure generate kar deti hai — hume manually folders aur files nahi banane padte.

Q7: Maven kya hai?
A: Maven ek build tool hai jo project ki dependencies (libraries) manage karta hai. Jab hum Spring Web add karte hain toh Maven automatically uski JAR files download kar leta hai.

Q8: application.properties file kya kaam aati hai?
A: Ye file Spring Boot ki configuration settings store karti hai — jaise server port, database URL, passwords etc.

Day 2
---
Q1: Project structure mein alag alag packages kyun banate hain?
A: Ye "Separation of Concerns" principle hai. Har package ka apna kaam hota hai — controller sirf requests handle karta hai, service business logic rakhta hai, model data structure define karta hai. Isse code readable, maintainable aur scalable banta hai.

Q2: Controller aur Service mein kya fark hai?
A: Controller HTTP requests receive karta hai aur response deta hai — ye sirf "traffic manager" hai. Service actual business logic karta hai jaise data process karna, calculations karna etc. Controller ko service pe depend karna chahiye, khud logic nahi likhna chahiye.

Q3: @RequestMapping kya karta hai?
A: Ye ek base URL define karta hai poore controller ke liye. Jaise @RequestMapping("/products") ka matlab hai is controller ke saare endpoints /products se shuru honge.

Q4: @PostMapping aur @GetMapping mein kya fark hai?
A: @GetMapping data fetch karne ke liye use hota hai — jaise products ki list lana. @PostMapping naya data create karne ke liye use hota hai — jaise naya product add karna.

Q5: @RequestBody kya karta hai?
A: Ye HTTP request ke body mein aaya JSON data automatically Java object mein convert kar deta hai. Jaise Postman se JSON bheja toh @RequestBody us JSON ko Product object bana deta hai.

Q6: @Autowired kya hota hai?
A: Ye Spring ka Dependency Injection feature hai. Iska matlab hai "Spring khud ProductService ka object banao aur yahan inject karo" — hume manually new ProductService() nahi likhna padta.

Q7: @Service annotation kya karta hai?
A: Ye Spring ko batata hai ki ye class ek Service component hai. Spring isko automatically detect karke apne context mein register kar leta hai taaki @Autowired se inject ho sake.

Q8: Abhi data restart pe kyun chala jata hai?
A: Kyunki hum data ArrayList mein store kar rahe hain jo memory mein hoti hai. Jab app restart hoti hai memory clear ho jati hai. Week 2 mein MySQL database add karenge tab data permanently save hoga.

Q9: Postman kyun use karte hain?
A: Browser sirf GET requests bhej sakta hai. POST, PUT, DELETE requests test karne ke liye Postman use karte hain — ye ek API testing tool hai jahan hum method, headers, aur body sab customize kar sakte hain.

Q10: JSON kya hota hai?
A: JSON (JavaScript Object Notation) ek data format hai jo APIs mein data exchange ke liye use hota hai. Ye human readable bhi hai aur machines ke liye bhi easy hai. Example: {"name": "Laptop", "price": 999.99}


Day 3

Q1: HTTP Status Codes kya hote hain?
A: Ye 3 digit numbers hote hain jo server client ko batata hai ki request ka kya hua. Inki categories hain — 2xx matlab success, 3xx matlab redirect, 4xx matlab client ki galti, 5xx matlab server ki galti.

Q2: Common Status Codes kaunse hain?
A: Sabse common codes ye hain — 200 OK matlab request successful rahi, 201 Created matlab naya resource ban gaya, 400 Bad Request matlab request mein kuch galat tha, 401 Unauthorized matlab authentication chahiye, 403 Forbidden matlab permission nahi hai, 404 Not Found matlab resource exist nahi karta, 500 Internal Server Error matlab server mein kuch gadbad hui.

Q3: ResponseEntity kya hota hai?
A: Ye Spring ka ek class hai jo HTTP response ko fully control karne deta hai — isme data bhi hota hai aur status code bhi. Pehle hum sirf data return kar rahe the, ab ResponseEntity se hum data ke saath proper status code bhi bhej sakte hain.

Q4: @PathVariable kya karta hai?
A: Ye URL ke andar se value extract karta hai. Jaise /products/1 mein 1 ek path variable hai. @PathVariable int id likha toh Spring automatically URL se 1 nikal ke id variable mein daal deta hai.

Q5: @PutMapping aur @DeleteMapping kya hote hain?
A: @PutMapping HTTP PUT request handle karta hai jo existing resource update karne ke liye use hota hai. @DeleteMapping HTTP DELETE request handle karta hai jo resource delete karne ke liye use hota hai.

Q6: GET aur POST aur PUT aur DELETE mein kya fark hai?
A: Ye sab HTTP methods hain — GET data fetch karta hai, POST naya data create karta hai, PUT existing data update karta hai, DELETE data remove karta hai. Inhe milake CRUD operations kehte hain — Create, Read, Update, Delete.

Q7: Stream API kya hai jo humne ProductService mein use kiya?
A: Java Stream API ek modern tarika hai collections pe operations karne ka. Humne productList.stream().filter().findFirst() use kiya — iska matlab list mein se filter karo aur pehla match wala element lo. Ye traditional for loop se zyada readable hota hai.

Q8: orElse(null) kya karta hai?
A: Jab findFirst() koi element nahi dhundh pata toh ye Optional return karta hai. orElse(null) ka matlab hai "agar kuch nahi mila toh null return karo". Isi null ko hum controller mein check karke 404 status dete hain.

Q9: CRUD kya hota hai?
A: CRUD ek concept hai — Create (POST), Read (GET), Update (PUT), Delete (DELETE). Koi bhi basic application in 4 operations pe chalti hai. Humne aaj pura CRUD complete kar liya!

Q10: Professional API structure kyun important hai?
A: Jab team mein kaam hota hai ya application badi hoti hai tab proper structure bahut zaroori hai. Controller sirf routing kare, Service business logic rakhe, Model data define kare — isse code maintain karna aur debug karna aasaan hota hai.


Day 4

Q1: Exception Handling kya hoti hai?
A: Jab program mein kuch galat ho jata hai toh exception throw hoti hai. Exception handling ka matlab hai us galti ko gracefully handle karna — program crash hone ki jagah user ko ek proper error message dena.

Q2: RuntimeException kya hoti hai?
A: Java mein 2 tarah ki exceptions hoti hain — Checked aur Unchecked. RuntimeException unchecked hoti hai matlab hume ise explicitly catch karna zaroori nahi. Humne ResourceNotFoundException ko RuntimeException extend karaya isliye Spring ise automatically handle kar sakta hai.

Q3: @ControllerAdvice kya karta hai?
A: Ye annotation ek class ko global exception handler bana deta hai. Matlab poori application mein kahi bhi koi exception throw ho, ye class usse pakad leti hai aur proper response return karti hai. Ek jagah se saari exceptions handle ho jaati hain.

Q4: @ExceptionHandler kya karta hai?
A: Ye annotation ek method ko specific exception ka handler bana deta hai. Jaise @ExceptionHandler(ResourceNotFoundException.class) ka matlab hai — jab bhi ResourceNotFoundException throw ho toh ye method call ho.

Q5: orElse aur orElseThrow mein kya fark hai?
A: Dono Optional pe kaam karte hain. orElse(null) ka matlab hai "agar value nahi mili toh null return karo" — ye safe nahi hota. orElseThrow() ka matlab hai "agar value nahi mili toh exception throw karo" — ye professional aur proper way hai kyunki null se NullPointerException aa sakti hai.

Q6: Custom Exception kyun banate hain?
A: Java mein built-in exceptions hain jaise NullPointerException, IllegalArgumentException etc, lekin ye generic hoti hain. Custom exception banane se code readable hota hai — ResourceNotFoundException padhke hi samajh aata hai ki kya problem hai. Alag alag situations ke liye alag exceptions bana sakte hain.

Q7: Error response mein timestamp kyun dete hain?
A: Timestamp se pata chalta hai exactly kab error aaya. Jab production mein koi bug aata hai toh developers logs mein us time ko dhundhte hain. Ye debugging aur monitoring ke liye bahut useful hota hai.

Q8: HashMap ka use error response mein kyun kiya?
A: Humne Map<String, Object> use kiya taaki flexible JSON response ban sake jisme multiple fields ho — status, message, timestamp, error. Ye ek common pattern hai error responses ke liye.

Q9: Agar GlobalExceptionHandler na ho toh kya hoga?
A: Bina exception handler ke Spring apna default error response deta hai jo bahut verbose aur confusing hota hai — usme stack trace aur unnecessary details hoti hain. GlobalExceptionHandler se hum clean, meaningful error responses de sakte hain.

Q10: Exception Handling best practices kya hain?
A: Kuch important practices hain — har situation ke liye meaningful exception banao, generic Exception mat pakdo, proper HTTP status codes use karo, error message user-friendly rakho, aur kabhi bhi stack trace user ko mat dikhao production mein.

Day 6


Q1. In-memory list ki kya problem hai?

Server restart karne pe saara data delete ho jata hai — data permanent nahi rehta


Q2. Auto ID ke liye kaunsa variable banaya?

private int nextId = 1; — ye har naye product ko automatically ID assign karta hai


Q3. addProduct mein ID kaise assign ki?

product.setId(nextId) se ID assign ki, phir nextId++ se counter badha diya


Q4. Pehle Product.java mein sirf getters the — kya add karna pada aur kyun?

Setters add karne pade — setId, setName, setPrice — kyunki product.setId(nextId) call karna tha service mein


Q5. Getter aur Setter mein kya fark hai?

Getter — field ki value padhta hai, Setter — field ki value set/change karta hai


Q6. 2 products add kiye bina ID diye — GET pe kya IDs aaye?

1 aur 2 — nextId counter ne automatically assign kiye


Q7. DELETE ke baad GET kiya — kya hua?

Deleted product list se remove ho gaya, sirf baaki products dikhe


Q8. Abhi data kahan store ho raha hai?

RAM mein — List<Product> mein, jo server restart pe empty ho jati hai


Q9. Is problem ka solution kya hoga?

MySQL database — Week 2 mein karenge, tab data permanently store hoga
